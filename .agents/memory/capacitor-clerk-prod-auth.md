# Capacitor native build → Clerk dev/prod instance mismatch

A native (Capacitor/Expo) build made from the **dev** environment bakes the
**dev** Clerk publishable key (`pk_test_…`, talks to `*.accounts.dev`) into the
JS bundle. If the same native app points its API calls at the **production**
server (common pattern — e.g. `main.tsx` calling `setBaseUrl(prodUrl)` on
native), the prod server validates Clerk tokens against the **production** Clerk
instance and rejects the dev-minted tokens. Result: client is signed in
(`isSignedIn === true`) but **every API request is treated as a guest**
(`userId === null`) — symptoms look feature-specific (e.g. empty profile,
"CLOSED"/locked content) but are actually global auth failure.

**Why:** Replit-managed Clerk has fully separate dev/prod instances; the
`pk_live` key is only swapped in at publish time and is NOT available in the dev
environment, and the clerk-auth skill forbids hardcoding Clerk keys. So you
cannot fix a bundled native build by baking prod creds from dev.

**How to apply / fix:** Make the native shell load the LIVE production site
directly via Capacitor `server.url = "https://<app>.replit.app"` (root
`capacitor.config.ts`). The WebView origin then becomes the production domain,
so the prod Clerk key, the `/api/__clerk` proxy, and same-origin session cookies
all line up exactly like the website. Only viable when the app is online-only
(no real offline mode lost). After editing, the user MUST run `npx cap sync
android` and rebuild/reinstall the APK — a code change alone never updates an
installed app, and `android/.../assets/capacitor.config.json` is regenerated by
sync.

**Diagnostic shortcut:** grep the synced bundle for the baked key/instance:
`rg -o "pk_(test|live)_[A-Za-z0-9]{6}|accounts\.dev" android/app/src/main/assets/public`.
`pk_test` + `accounts.dev` in a build that talks to prod = this bug.
